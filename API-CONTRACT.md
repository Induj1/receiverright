# API contract - frontend and backend

API prefix `/api`. Errors `{error: string, code?:string, details?:unknown}`. Receiver auth `Authorization: Bearer <session.token>`. JSON unless upload. Data types in shared/types.ts. Reconciliation computed with `reconcileCase(caseRecord)` exported shared/domain.ts. Server returns record fields without storage/internal auth keys. Dates ISO; all money integer paise.

- GET /health -> Health
- POST /sessions {name?:string} -> Session plus `expiresAt:string` (ISO). Creates an isolated workspace and a seven-day session. Demo uses labeled sample fixtures, never real-customer data. Token only generated by server, scoped to workspace, stored as a hash locally or in DynamoDB.
- GET /workspace -> `{recoveryEnabled:boolean,recoveryUpdatedAt?:string,sessionExpiresAt:string}`. Requires receiver authentication; dates are ISO strings.
- POST /workspace/recovery {} -> `{recoveryCode:string,createdAt:string,notice:string}`. Requires receiver authentication. Generates a cryptographically random, case-sensitive recovery code, or replaces the current code. The plaintext is returned only at generation; storage keeps its hash and a workspace mapping. Replacement invalidates the old recovery code but does not revoke existing unexpired sessions.
- POST /sessions/recover {recoveryCode:string} -> Session plus `expiresAt:string` (ISO). Does not require an active session. A valid saved recovery code issues a fresh seven-day session for the same workspace. Invalid/replaced codes return 401 `INVALID_RECOVERY`; persistent per-source attempt limits return 429 `RECOVERY_RATE_LIMIT`. Recovery must have been configured before browser access was lost.
- POST /sessions/renew {} -> Session plus `expiresAt:string` (ISO). Requires an unexpired receiver session. Extends that same session token for seven days from renewal; an expired session returns 401 and requires recovery.
- GET /cases -> {cases: ReceivingCase[]}
- POST /cases {supplier, invoiceNumber?, shopName?, invoiceDate?, lines?} -> ReceivingCase, empty draft supported
- POST /cases/sample {} -> ReceivingCase. Creates sample invoice with 3 lines and invoice evidence (public sample asset); must not claim AWS extraction.
- GET /cases/:id -> ReceivingCase
- GET /cases/:id/revisions -> `{revisions:SnapshotMetadata[],notice:string}`. Requires the owning receiver session; newest saved state first. Each metadata item has `snapshotId:string`, `revision:number`, `savedAt:string`, `action:string`, `status:CaseStatus`, `lineCount:number`, `evidenceCount:number`, `responseCount:number`, `isCurrent:boolean`, and optional `legacyBaseline:boolean`.
- GET /cases/:id/revisions/:snapshotId -> `{snapshotId:string,savedAt:string,record:ReceivingCase,reconciliation:Reconciliation,notice:string}`. Requires the owning receiver session. Returns a read-only saved state with its content, evidence references, and supplier responses. Missing or another workspace's cases/states return 404. Snapshot IDs identify storage mutations, so multiple snapshots may share an invoice-content revision.
- PUT /cases/:id {revision:number, ...editableCaseFields} -> ReceivingCase. Editable: supplier,supplierEmail,shopName,invoiceNumber,invoiceDate,lines. Optimistic concurrency 409; edits invalidate prior sharing by revision and remove current responses, preserve history.
- POST /cases/:id/ready {revision} -> ReceivingCase. Requires reconciliation.ready, sets ready.
- POST /cases/:id/share {revision} -> ShareResult, sets shared at same revision; secure random token and six-digit PIN; store hashed PIN, bounded attempts, expiry. Public share endpoint must require both link token and PIN, never expose receiver access.
- POST /cases/:id/close {revision} -> ReceivingCase. Requires all discrepancy lines acknowledged, records closure as acknowledged not recovered money.
- POST /cases/:id/summary {} -> {summary:string, provider:'template'|'bedrock'}
- POST /uploads {caseId,fileName,mimeType,kind,lineId?,size} -> {uploadId,uploadUrl,method:'PUT',headers:Record<string,string>}. Returned URL may be local API upload or S3 presigned. Frontend PUT raw File bytes with returned headers.
- POST /uploads/:id/complete {} -> Evidence; verifies upload then attaches to case. Invoice evidence may be extracted next.
- POST /cases/:id/extract {evidenceId} -> ExtractionResult, does not overwrite current lines until receiver confirms saving. If AWS unavailable return explicit 503, manual input remains available; no fake extraction.
- GET /evidence/:id -> image/PDF stream or private signed redirect. The owning receiver can read historical attached evidence; a supplier session can read evidence belonging to its current, authorized review. S3 downloads use the checked object version. Frontend may fetch a blob for image rendering.
- POST /shares/:shareId/open {pin} -> {token:string,case:ReceivingCase}. Supplier token bearer for subsequent calls. Failed auth no case details.
- GET /shares/:shareId -> {case:ReceivingCase}, supplier bearer; reject stale revision.
- POST /shares/:shareId/respond {revision,responses:[{lineId,decision,note}],name} -> ReceivingCase. Supplier bearer. Validate line IDs, decision/note and revision. History records responding name as supplied name, not verified legal identity.
- GET /cases/:id/export?format=json|csv -> attachment

Local assets: /sample-invoice.svg, /sample-delivery.svg; demo evidence URLs public only for synthetic sample. Runtime config health lets UI honestly show local vs AWS. Supplier response page URL `/review/:shareId`.

Saved-history behavior: the current record, its new snapshot, and snapshot index are committed in one conditional transaction. Changes within a content revision, including supplier responses, receive separate saved states. Edits advance the content revision and clear current responses while earlier snapshots remain available. Records predating this feature retain their available migration baseline and later changes; earlier overwritten content cannot be reconstructed. Each record body is limited to 350,000 UTF-8 JSON bytes, with up to 1,000 storage-version saved states. Oversize changes return 413 `CASE_SIZE_LIMIT`; the saved-state limit returns 409 `CASE_HISTORY_LIMIT`, without silently deleting old states. These application records are not a legally certified archive.

Domain rules: receivedQty includes every physically received unit allocated to line, including damaged/wrong. damaged and wrong are mutually exclusive and sum <= received. Accepted=received-damaged-wrong. Shortage=max(expected-received,0). Discrepancy=shortage+damaged+wrong; excess tracked separately. Pack conversion required for carton/pack units; priceMinor is per billed unit, so piece value price/pack and round only final line value. Non-finite/negative values and unconfirmed lines block ready. No tax/discount calculation.
